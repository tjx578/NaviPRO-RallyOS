# 2. Ya — OpenAPI Spec Bisa Menjadi Dasar MCP

Ada dua hal berbeda.

### A. OpenAPI → Custom GPT Actions

Ini didukung langsung. Custom GPT Actions menerima OpenAPI JSON/YAML dan membaca `servers`, endpoint, parameter, authentication, dan khususnya `operationId`. ([help.openai.com](https://help.openai.com/en/articles/9442513-configuring-actions-in-gpts?utm_source=chatgpt.com))

Misalnya:

```yaml id="kq0699"
paths:
  /routes/{routeId}:
    get:
      operationId: getRoute
      summary: Get NaviPRO route

  /routes/{routeId}/validate:
    post:
      operationId: validateRoute
      summary: Validate rally route
```

GPT otomatis melihat:

```text id="pstr07"
getRoute()
validateRoute()
```

---

### B. OpenAPI → MCP

Di sini pendekatannya:

```text id="pkufb4"
openapi.yaml
     │
     ▼
OpenAPI MCP Adapter
     │
     ├── operationId → MCP tool
     ├── schema      → inputSchema
     ├── description → tool description
     └── API call    → tool execution
```

Jadi misalnya:

```yaml id="6vwclt"
operationId: validateRoute
```

menjadi:

```text id="r3u1o5"
MCP Tool
navipro_route_validate
```

**DERIVED:** dengan demikian kita tidak perlu menulis definisi tool MCP dua kali.

# 3. Bahkan Lebih Baik: Tambahkan Metadata NaviPRO

Saya akan membuat OpenAPI NaviPRO sedikit lebih pintar.

Contoh:

```yaml id="ef1h5z"
/routes/{routeId}/validate:
  post:

    operationId: validateRoute

    tags:
      - Route

    x-navipro-tool: true
    x-navipro-domain: route
    x-navipro-authority: read
    x-navipro-agent: rally
```

Untuk mutation:

```yaml id="9dg7f3"
/routes/{routeId}/activate:
  post:

    operationId: activateRoute

    x-navipro-tool: true
    x-navipro-domain: route
    x-navipro-authority: navigator-confirmation
```

MCP generator kemudian bisa membaca:

```text id="69plf9"
x-navipro-tool = true
```

dan hanya mengekspos endpoint tersebut.

Ini lebih aman daripada:

> “Semua endpoint OpenAPI otomatis menjadi MCP tool.”

# 13. Bagaimana Kalau Langsung MCP App di ChatGPT?

Juga bisa, tetapi ada kondisi produk.

Full custom MCP Apps di ChatGPT—termasuk write/modify actions—saat ini sedang rollout beta untuk **Business, Enterprise, dan Edu**. ChatGPT menghubungi remote MCP server; server lokal tidak langsung digunakan kecuali melalui mekanisme tunnel yang didukung. ([help.openai.com](https://help.openai.com/en/articles/12584461-developer-mode-apps-and-full-mcp-connectors-in-chatgpt-beta?utm_source=chatgpt.com))

OpenAI juga merekomendasikan Apps SDK untuk mengemas pengalaman aplikasi ChatGPT yang memakai MCP. ([help.openai.com](https://help.openai.com/id-id/articles/11487775?utm_source=chatgpt.com))

Jadi nanti secara teoritis:

# 17. Authority Gate Tetap Diperlukan

Tidak semua endpoint OpenAPI boleh otomatis diekspos ke AI.

Contoh:

```text id="bysphb"
READ
route.get
location.search
timing.calculate
       │
       └── agent boleh otomatis
```

Sedangkan:

```text id="mdlli8"
WRITE
route.delete
route.confirm
route.activate
tsd.send
       │
       └── authority gate
```

Saya akan menaruh metadata seperti:

```yaml id="mzmfcp"
x-navipro-authority: navigator
x-navipro-confirmation: required
```

Dengan demikian:

```text id="0slzbh"
MCP generator
       │
       ▼
Authority Middleware
       │
       ├── READ → execute
       │
       └── WRITE → navigator approval
```

# Sintesis Keputusan

| Opsi | Bisa? | Posisi yang tepat |
|---|---:|---|
| OpenAPI → GPT Actions | **Ya** | prototype/client |
| OpenAPI → MCP | **Ya, melalui adapter/generator** | arsitektur utama |
| Custom GPT sebagai NaviPRO utama | Tidak saya sarankan | optional client |
| ChatGPT Project | **Ya** | knowledge/workspace |
| Project sebagai backend | **Tidak** | bukan runtime |
| NaviPRO Page 3 → MCP | **Ya** | sangat direkomendasikan |
| Repo | Tidak diwajibkan protokol | **direkomendasikan kuat** |
| MCP sebagai core business logic | Tidak | interface/orchestration |
| NaviPRO Core/API sebagai pusat | **Ya** | SSOT runtime |
